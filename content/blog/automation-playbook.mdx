«Автоматизируй бизнес» звучит как мантра, но на практике 70% проектов автоматизации проваливаются: либо инструмент не подходит процессу, либо никто не поддерживает после внедрения, либо экономия меньше стоимости.

Этот playbook - наш опыт внедрения автоматизации в 20+ казахстанских компаниях. Делимся тем, что работает.

## Шаг 1. Какие процессы автоматизировать первыми

Формула простая:

> **ROI автоматизации = (часы × ставка × 12 мес) − стоимость внедрения и поддержки**

Хорошие кандидаты для первой волны:

- **Повторяемые** - происходят ≥10 раз в неделю
- **Предсказуемые** - есть чёткие правила (if-then)
- **Болезненные** - сейчас их делают вручную, ошибаются
- **Измеримые** - можно посчитать время/деньги до/после

Плохие кандидаты (не берите первыми):

- Редкие (раз в квартал)
- С большим числом исключений
- Требующие субъективной оценки
- Вовлекающие много отделов на первом шаге

## Шаг 2. Три уровня автоматизации

### Уровень 1. No-code интеграции (Zapier, n8n, Make)

Хороши для:

```text
Действие в системе A → уведомление/запись в системе B
```

Примеры:

- Новый клиент в Kaspi → карточка в CRM + Telegram в чат
- Оплата в 1С → email клиенту с чеком
- Звонок пропущен → задача на менеджера

**Стоимость:** от $20/мес, внедрение - дни.

<Callout type="info" title="Когда не хватит">
No-code упирается, когда сценариев становится больше 20, или нужна сложная логика
ветвления, или требуются кастомные API-вызовы. Тогда - уровень 2.
</Callout>

### Уровень 2. Кастомные pipeline на Node.js / Python

Когда no-code становится spaghetti из 30 зепов, которые никто не понимает.

Переходим на управляемый код:

```typescript
// Пример: автосчёт после оплаты
export async function handlePayment(payment: Payment) {
  const invoice = await generateInvoice(payment);
  await storeInDb(invoice);
  await sendEmailWithPdf(payment.clientEmail, invoice);
  await notifyTelegram(invoice);
  await syncTo1C(invoice);
}
```

**Преимущества:**
- Один git-репозиторий - весь бизнес-процесс виден
- Тесты, типы, code review
- Никаких лимитов по количеству задач

**Стоимость:** 2-6 недель разработки + хостинг.

### Уровень 3. Собственная платформа

Когда у вас 10+ процессов, 5+ отделов, нужна админка и roles. Это уже внутренний SaaS.

Пример - мы строили для клиента из логистики: документооборот, склад, интеграция с банком, учёт ГСМ. Vendors вроде 1С + SAP не подошли по цене и гибкости.

## Шаг 3. Метрики успеха

Перед внедрением зафиксируйте baseline:

| Метрика | До | Цель | Как меряем |
|---------|----|----|------------|
| Время обработки заказа | 2 ч | 15 мин | Лог в CRM |
| Ошибок в документах | 8% | &lt;1% | Проверка за месяц |
| Стоимость 1 заказа | ₸2 000 | ₸400 | Зарплата / количество |
| Время ответа клиенту | 4 ч | 30 мин | First-response метрика |

Через 30 дней после внедрения - сверка. Если не достигли - разбираемся почему.

## Шаг 4. Типичные ошибки

<Callout type="warn" title="Автоматизация плохого процесса">
Перед внедрением перечитайте процесс as-is. Если он кривой - сначала выпрямите его,
потом автоматизируйте. Иначе просто будете ошибаться быстрее.
</Callout>

**Другие грабли:**

- Нет owner'а внедрения - процесс повисает через месяц
- Нет документации - когда сотрудник уходит, никто не может поддерживать
- Экономят на мониторинге - узнают про сбой через неделю от клиентов
- Не учли edge cases - «а что если клиент два раза нажал оплатить?»

## Вывод

Автоматизация - это не IT-проект, а продуктовый. Нужно:

1. Сначала понять процесс
2. Выбрать правильный уровень сложности (не пушить код если хватит Zapier)
3. Измерить до и после
4. Назначить owner'а и писать документацию
